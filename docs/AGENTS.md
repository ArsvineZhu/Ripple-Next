# Documentation rules

- English is canonical; maintain the paired en/zh-CN guides and synchronize four product READMEs.
- README orients readers; INDEX maps destinations. Development owns commands/tooling, release owns publication/acceptance, platform-compatibility owns native support/recovery, architecture owns current capabilities/ownership.
- Describe the current correct implementation and user actions. Keep changelogs in versioned release notes and capture facts in asset provenance; remove progress logs and refactor narration from maintained guides.
- Confirm facts against schemas, source owners and package scripts. Keep important scopes discoverable, links valid and agent instructions concise technical English.
- Use actual English application screenshots/recordings with isolated demo data; language-specific examples use their corresponding locale. Document provenance and inspect all refreshed media.
- Write 4.1.0-beta.1 documentation for the delivered post-merge state. Actual PR merge/publication remains gated by the user's explicit confirmation.
